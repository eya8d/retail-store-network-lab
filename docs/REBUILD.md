# Rebuild guide

## Existing uploaded simulation

Download [Retail-Store-Network.pkt](../Retail-Store-Network.pkt) from the repository root and open it in Packet Tracer. The builder has reported applying targeted cleanup and confirming representative services afterward. Preserve a backup before experiments.

The files in configs/observed are historical sanitized exports, not final cleaned exports. The fresh-build templates include optional credential/console hardening that has not been confirmed applied to the .pkt. Do not assume their demonstration credentials describe the uploaded simulation.

## Fresh topology

1. Create/cable devices per TOPOLOGY.md; record application version.
2. Use matching device files in configs/build/ only on fresh corresponding devices. They explicitly create VLANs, configure interfaces, accounts and policy. Stop on unexpected parser errors rather than skipping them.
3. Generate RSA keys separately on R1/SW1/SW2 from config mode using crypto key generate rsa; enter 2048 when prompted. ISP does not need SSH in this design. Never delete keys on the working topology merely to change the domain typo.
4. Old endpoint-specific sticky MAC lines are intentionally absent from fresh templates. Connect only intended devices, generate traffic, inspect show port-security address, then save.
5. Enter endpoint and service GUI settings below. No .pkt is generated by these text files.
6. Verify show ip interface brief, show interfaces trunk, show vlan brief, ACL counters and DHCP leases before acceptance testing.

|---|---|
| Internal Server-PT | 192.168.40.10/24; gateway 192.168.40.1; DNS itself; HTTP and DNS On |
| Internal DNS | portal.retail.test → 192.168.40.10; www.public.test → 198.51.100.10; A records |
| PUBLIC-WEB | 198.51.100.10/24; gateway 198.51.100.1; HTTP and DNS On |
| External DNS | www.public.test → 198.51.100.10; A record |
| Printer | 192.168.20.10/24; gateway 192.168.20.1 |
| Admin-01 | 192.168.60.10/24; gateway 192.168.60.1; DNS 192.168.40.10 |
| Employee PCs | DHCP on wired interface |
| Guest AP | Retail-Guest SSID; WPA2-PSK/AES if available; lab-only passphrase; SW1 Fa0/8 VLAN50 |
| Guest clients | Correct SSID/key; DHCP on Wireless0; DNS 198.51.100.10 |

Use the AP's actual supported security options and record the final chosen setting; the exact GUI configuration is not present in IOS exports. A generic AP need not expose a separate management IP option. Keep it bridging guest traffic, not serving a second DHCP/NAT network.

Internal/external DNS records are manually duplicated; forwarding is not implemented. HTML portal pages represent services, not real sales or inventory software. Test availability with the browser because POS/Warehouse server ICMP echo requests are intentionally denied.

## Save

After traffic has populated correct sticky addresses and tests pass:

```text
copy running-config startup-config
```

Save your rebuilt file under a distinct name; the repository already contains Retail-Store-Network.pkt at its root. Reopen a copy and repeat service/management tests. Replace corrected-template status with final verified exports only after this process.
